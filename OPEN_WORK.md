# envlib ingestion — Open Work

The **datasets/ingestion track** of the envlib project: this toolkit, the per-source ingest
repos (`envlib-ingest-*`), dataset selection/licensing, and the tethys→envlib data migration.
Stack *development* (envlib/cfdb/ebooklet package work) is tracked separately in
`envlib-repos/envlib/OPEN_WORK.md`. Same conventions: **verification debts** (work done but
not yet proven; remove once the close-check passes) + **backlog**; completed items move to
**`OPEN_WORK_DONE.md`** (newest first). Sessions always launch from the envlib hub repo regardless of track.

- [ ] **[toolkit + ingest/ecan] Rain: the first hour of every fetch window is stored truncated** (found 2026-11-20, round `ecan-verify-code-1` in `forecasts-repos/ecan-flow-forecasts`, by the Fable arm; verified there). ECan's endpoint 78 returns a *partial* total for the hour in which a request window starts. `_resample_sum` credits a fetch's first reading a full slot (`resample.py`, `spans = np.concatenate([[float(med[0])], ...])`), so the short value passes the coverage rule. `merge_dataset` then overwrites the stored full total with it, because the incoming value is finite. So the hourly `2_Days` run damages the hour ~48 h back, until the next daily sweep repairs it. The daily `1_Week` sweep at 12 UTC damages the hour 7 days back, and **nothing repairs that one**. Measured in the stored data against ECan direct: every difference of 1 mm or more is envlib-low, at 12 UTC or ~50 h old, and envlib reads exactly 0.5 mm in each case. Examples: 315510 on 26 Oct 12:00 is 6.0 at ECan and 0.5 in envlib, and 316310 at the same hour is 4.0 against 0.5. **It reaches the live forecast:** the model's measured-rain window is 96 h, so the ~48 h damage sits inside every run's inputs whenever that hour had rain. Fable's perturbation test saw no effect at 60 and 90 h back, and 48–59 h was not tested. **Measured effect on live runs** (`verification/replay.py --rain ecan`, 2026-11-20): runs that reproduce the archive exactly on envlib's stored rain move by 0 to 1.1 m³/s when fed ECan's untruncated rain (9–15 Nov, a quiet period). The effect during an event is unmeasured. **Likelihood: ordinary**, on every fetch whose first hour had rain. The magnitude per run is small in quiet weather. **Fix direction (not built):** drop the first output interval of each fetch window before merging, or have `_resample_sum` give a fetch's first reading no coverage, as it already does for a lone reading. Whichever is chosen, the hour must be re-fetched by a later window rather than left NaN. Check the flow path too: `'mean'` has its own first-slot handling, and the 2026-11-20 comparison saw flow agree to ±0.1 m³/s inside the window, so flow looks unaffected. **Close-check:** after the fix, ECan direct (`Period=1_Month`) and envlib agree at every hour more than one window old, with zero envlib-low hours at 12 UTC and at ~48 h. `ecan-flow-forecasts/verification/score.py` prints that comparison.
